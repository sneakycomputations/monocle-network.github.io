Community Reserves

Haveno Network Development Grant

Monocle allocates a portion of collected network fees to support ongoing development of the Haveno project, ensuring the software continues to evolve and improve.

Scope of the Haveno Network Development Grant

Haveno Network Development Grant will be used to sponsor bounties, which will be posted as issues on the Haveno GitHub repository.

Example bounties could be:

  • Adding support for more payment methods or cryptocurrencies
  • Launching a bug bounty
  • Auditing Haveno source code for vulnerabilities
  • Improving the UI for participants and arbitrators
  • Supporting specific development work

Bounty distributions occur upon completion of accepted work. The bounty claimer posts their XMR address on the issue. The transaction ID and secret transaction key are then published as a comment, allowing anyone to independently verify that the bounty has been distributed.

For development work, which is anticipated to be mostly pull requests, distribution will occur when the pull request has been merged in a release.

If there is disagreement about whether the work meets the acceptance criteria, the final decision will be made by community consensus in Monocle's public discussion spaces.

Bounties that remain unclaimed for 12 months may be cancelled and funds reallocated to other bounties.

Bounty Evaluation Process

The bounty program is designed to be community-led. While bounty-funded improvements benefit all Haveno networks, the direction of which bounties receive funding should come from the Monocle community. If a significant portion of network peers want to see a particular feature, that is what will be prioritized. The goal is for the community to help shape the Haveno they want to see.

Developer Application

As the bounty program is community-led, developers are free to engage with the Monocle community to discuss their ideas. If the community wishes to grant a proposal, the bounty will be created.

Approval for Code Auditing

The bounty program is guided by community priorities. Auditors interested in reviewing Haveno's code for vulnerabilities should engage with the community to obtain approval, which will be based on a defined audit period and scope.

As the Haveno Network Development Grant program is community-led, it is up to the community to determine whether expectations have been met, and the bounty should be distributed. The process of community consensus has yet to be defined.

Denomination of Bounties

Bounties will be denominated in XMR.

Bounty Liquidity

Monocle Network will only open bounties for up to the XMR amount available in Haveno Network Development Grant, however, in the event of an exploit, peer reimbursement takes priority and bounties may be temporarily withdrawn.
